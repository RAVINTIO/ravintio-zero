# Changelog (0000411-queue-waits, 09 Nov 2026)

**Feature:** The merge queue waits for GitHub before it merges
**Version:** no bump. This PR is not a chart step of initiative 0000360.
**PR:** pending

## What changed

- After each push, `merge-queue.mjs` waits until GitHub shows the pushed head, then waits for CI on it.
- Before the squash, it waits until GitHub reports the PR `MERGEABLE` with a clean state.
- A "not mergeable" or "Base branch was modified" refusal gets one retry.
- A wait past `MQ_TIMEOUT_MS` stops with `timed out waiting for PR #{n}: {what}`.
- A new suite, `test-0000411-req-001-queue-waits.sh`, runs the queue against a slow fake GitHub. The fake `gh` in the 0000378, 0000392, and 0000405 suites answers the new query.

## Why

On 2026-11-08 and 2026-11-09 the queue stopped with "Pull Request is not mergeable" on steps 8, 9, 10, 11, 13, and 16 of initiative 0000360. It merged straight after a push, before GitHub had checked the new head. Each stop needed a manual retry.

## Deviations

- Step 16 (0000392) merged a CI wait into the same script during this run. This change builds on it and uses its `MQ_POLL_MS` and `MQ_TIMEOUT_MS` settings, not new ones.
- P2 ran inline without subagents, because the change is one unit in one script.
