# Changelog (0000580-log-non-tdd-units, 26 Nov 2026)

**Feature:** Log a non-TDD unit with a class
**Version:** set by the merge queue at merge
**PR:** pending

## What changed

- The dispatch standards name a fifth unit class, `docs`, for a unit with no executable check. Its tier row matches `content`.
- The rule `dispatch-docs-markers` says a `docs` unit still logs `RED:` and `GREEN:` lines that carry its class.
- `build-log-mark.mjs` takes `--class` for `RED` and `GREEN` lines.
- Check 7 of `build-log-check.mjs` requires both markers for a `docs` `Done:` line, as for tier `inline`.
- `workflow-metrics.mjs` counts `docs` units in a row named `docs`.
- Four suites cover the changes. ADR 0353 records the decision.

## Why

A living-docs unit has no test, so it had no valid `Done:` form. Step 10 logged one with no class, and the report counted it as `unclassified`. Backlog entry 0000410 filed the gap.

## Deviations

- No check relaxes. The chart decision for 0000410 required it, so the class adds markers and removes none.
- `git fetch` failed in the sandbox, so the plan read branch-point files from the local tracking ref.
- The agent ran units U-001 to U-005 inline in one tree and dispatched no subagent, because each unit is one small change.
