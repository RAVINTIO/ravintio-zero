# Changelog (0000316-hooks-fail-closed, 31 Oct 2026)

**Feature:** Hooks fail closed
**Version:** 0.42.0
**PR:** pending

## What changed

- `setup.sh` and `setup.ps1` set `CLAUDE_BASH_MAINTAIN_PROJECT_WORKING_DIR` to `1` under `env` in `.claude/settings.json`. They keep other `env` entries and leave one copy after a rerun.
- Both scripts wire every Claude Code hook as `node "${CLAUDE_PROJECT_DIR}/.claude/hooks/enforcement/guard-run.mjs" {guard|advisory} {hook}.mjs`. The Codex `merge-guard` command holds the absolute project path.
- New `ravintio-zero/hooks/enforcement/guard-run.mjs`. In guard mode a missing script, a crash, a signal, or any exit other than 0 and 2 exits 2 and names the script. In advisory mode a missing script exits 0 and is reported once.
- Two new setup suites and one launcher suite cover the changes. Nine older suites and one fixture now expect the launcher command form.
- `hook-enforcement.md`, the architecture overview, and the decisions index describe the launcher.

## Why

A `cd` in one Bash command moved the working directory, and every relative hook path then failed with exit 1. Claude Code treats exit 1 as non-blocking, so `gate-write`, `merge-guard`, `ratchet-check`, and `em-dash-guard` allowed every call until the directory returned to the root. Backlog entries 0000287 and 0000288 asked for the fix.

## Deviations

- The launcher stays unguarded. If `guard-run.mjs` itself is missing, its command exits 1 and the guards allow. Setup copies it with the hooks, and the setup rerun check runs every hook. The risk register records the gap.
