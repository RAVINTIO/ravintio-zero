# Changelog (0000357-guard-gaps-closed, 06 Nov 2026)

**Feature:** Guard gaps closed
**Version:** 0.54.0
**PR:** 116

## What changed

- Each guard-mode hook command that `setup.sh` and `setup.ps1` write ends with ` || exit 2`. A missing `guard-run.mjs` or a missing `node` now blocks the call. This covers the Claude Code commands and both Codex commands. Advisory commands keep their form.
- `block-forced-add.mjs` reads `git stage` like `git add`. It reads a subshell, a command substitution, a backtick, and a brace group as separate segments. It blocks a segment with `$` when the git subcommand is `add`, `stage`, or a variable, and it blocks a variable glued to `git`. A commit message that holds `$` still passes.
- Setup copies `block-forced-add.mjs` into the Codex hooks folder and wires it as a second Bash group, in both setup scripts. The report and `hook-enforcement.md` list it as an active Codex hook.
- `ravintio-zero/.gitignore` and this repo's `.gitignore` hold `plan/.prefix-misses.log`.
- Backlog entries 0000340, 0000341, and 0000342 are pulled in and deleted.

## Why

A missing launcher made `node` exit 1, which Claude Code treats as non-blocking, so every guard failed open at once. The forced-add guard missed three forms, and Codex had no forced-add guard. A fresh clone did not ignore the prefix-misses log, so the CI ignored-file check would miss a forced add of it.

## Deviations

- Advisory commands do not get the exit 2 suffix. Exit 2 on a Stop or UserPromptSubmit hook blocks the session, so the chart row applies to guard-mode commands only.
- Units ran inline, not as subagents.
- Tests that pinned the old guard command text now read the suffix. `test-0000316` counts two Codex hooks.
- The ignore rule reaches a consumer repo only when setup creates its `.gitignore`. Setup keeps an existing file.

- 8 criteria verified by execution. 0 failed. 1 not-verifiable here: the hook check after the setup rerun, which the coordinator runs.
- Security review found no critical, high, or medium findings.
