# Changelog (0000392-ship-postmortems, 08 Nov 2026)

**Feature:** Ship postmortems
**Version:** set by the merge queue at merge
**PR:** #134

## What changed

- Ship Step 3 now fails a build log that has a `Resolved:` line or a reworked requirement with no `Postmortem:` line (0000285).
- `scripts/postmortem-check.mjs` checks that a postmortem holds one corrective, preventive, and detective row. A row reads `none, because {reason}` when a type has no action. A `done` row names its commit or PR.
- The postmortem template and skill use a CAPA table. The orchestrator runs the skill for each `Rework:` line, and writes the `Resolved:` line first when someone clears a stop outside the session.
- The merge queue waits for every check on the version commit it pushes, and stops with the failing check name (0000403).
- The ship skill names the PR title form `{feature-id}: {Feature title}` with a seven-digit id, and runs `merge-queue.mjs title` before `gh pr create` (0000403).

## Why

No run wrote a postmortem unprompted, and nothing checked for one. The merge queue stopped steps 4 and 9 on a title mismatch and a refused merge.

## Deviations

- The first full suite run failed three suites that pinned lines the step edited. The step restored the pinned wording. A postmortem records the cause: `plan/postmortems/2026-11-08-step-16-tests-pinned-edited-lines.md`.
